# TCS CodeVita
> **Organizer:** Tata Consultancy Services (TCS) | **Type:** Competitive Programming & Recruitment Drive | **Frequency:** Annual | **Difficulty:** Advanced / Elite

This folder contains resources and blueprints for preparing for **TCS CodeVita**, the world's largest competitive programming contest. Achieving an elite rank in this contest serves as a high-yield recruitment pipeline for TCS's most prestigious and highly compensated engineering roles (Ninja, Digital, and Prime).

## Exam Pattern
TCS CodeVita uses dynamic time-based tie-breakers where candidates with the same score are ranked by the total time taken to successfully execute solutions from the start of the contest.

* **Round 1 (Pre-Qualifier):** Online, unproctored 6-hour coding contest with 6 algorithmic questions of varying difficulty. Strict AST-based similarity checks (like Stanford MOSS) filter plagiarism.
* **Verification Round (Tag Test):** Critical offline, proctored 90-minute exam at a TCS iON center. Candidates must solve 2 algorithmic problems (1 easy-medium, 1 medium-hard) without internet or external assistance.
* **Round 2 (Qualifier):** Online 8-hour contest with 8 complex algorithmic challenges for top R1 coders.
* **Grand Finale:** In-person 10-question final at TCS offices competing for a global $20,000 USD prize pool.

## Syllabus
CodeVita does not publish a static syllabus, but heavily tests core algorithmic domains:
* **Arrays & Strings:** Contiguous array manipulations, sliding windows, and string parsing logic.
* **Linear & Non-Linear Structures:** Stacks, Queues, Linked Lists, BSTs, Segment Trees, Hash Maps, and Graph Adjacency.
* **Optimization & Exploratory Logic:** Dynamic Programming (DP), Greedy algorithms, Binary Search, Backtracking, BFS/DFS, Dijkstra's and shortest-path algorithms.
* **Computational Math:** Prime theory, Combinatorics, Modulo Arithmetic, and Bitwise manipulation.
* **Time Complexity Constraints:** Solutions must operate within 1-2 second limits (requiring logarithmic or linearithmic optimizations rather than brute-force quadratic algorithms).

## Target Score (General Category)
* **Round 1 (Pre-Qualifier):** Fully solve 1 to 2 highly complex problems or partially execute 3 problems. Aiming for a global rank under 1,000 ensures a direct interview/Tag Test invite.
* **Tag Test (Verification):** Complete the easy-to-medium problem and pass public test cases for the medium-to-hard problem for standard roles. Flawless execution of both is required for the Prime profile.

## Preparation Timeline
* **Phase 1: Foundation (Months 1-2):** Language syntax, Contiguous memory, basic math, and STL/Collections.
* **Phase 2: Intermediate (Months 3-4):** Linear structures, trees, binary search, and greedy approaches.
* **Phase 3: Advanced (Month 5):** Dynamic Programming (DP), graph traversals, and backtracking state-spaces.
* **Phase 4: Simulation (Month 6):** Timed 90-minute bare-notepad coding tests mimicking the proctored Tag Test.

## Top 5 Tips
1. **Master DP and Graph Algorithms:** These are the primary gatekeepers of the high-ranking cutoffs and elite packages.
2. **Simulate the Tag Test Environment:** Write code on basic text editors without IDE autocomplete or external search tools to build syntax recall.
3. **Analyze Big-O Limits Preemptively:** Determine complexity requirements based on input bounds before implementing code to avoid TLE.
4. **Leverage Language Collections:** Rely on built-in C++ STL or Java Collections rather than writing custom data structures from scratch.
5. **Accept Presentation Errors (PE):** PE is functionally treated as accepted; immediately skip to the next question without trying to fix whitespace formatting.

## Common Mistakes to Avoid
* **Plagiarism and AI Dependency:** Copying code or using LLMs in Round 1. Graders catch logical control-flow similarities instantly, leading to immediate disqualification.
* **Mid-exam GitHub Commits:** Freshly committing code to personal GitHub pages mid-exam to create attribution links violates the honor code.
* **Missing Boundary Constraints:** Forgetting 64-bit integer variables (like `long long`) or array limit checks, resulting in runtime integer overflow or memory crashes.
* **Wasting Time on Presentation Errors:** Obsessing over stdout spacing instead of securing points on other questions.
